FAZMAIS
Catálogo Educacional Inteligente
Product Requirements Document (PRD)
v1.0 — Agosto 2026

1. Visão Geral do Produto
O FazMais é uma plataforma multi-tenant de catálogo educacional que permite municípios organizarem e disponibilizarem conteúdos pedagógicos (vídeos e PDFs) para professores da rede. A interface do professor segue o padrão Netflix de consumo de conteúdo, enquanto o administrador gerencia acervos, coleções e usuários. Um usuário Master tem visão global sobre todos os municípios.
1.1 Objetivos
• Centralizar o acervo educacional de cada município em uma plataforma única e organizada
• Facilitar a descoberta de conteúdos relevantes pelo professor através de IA
• Permitir gestão autônoma por cada município (multi-tenancy completa)
• Oferecer experiência de consumo moderna e intuitiva para o professor
1.2 Personas
Master — Super administrador da plataforma. Cria municípios e seus admins. Visão global.
Administrador — Diretoria de ensino do município. Gerencia acervos, coleções, conteúdos e usuários do seu tenant.
Professor — Consumidor final. Navega, busca, favorita, avalia e consome conteúdos.

2. Stack Técnica
Arquitetura: Monorepo com Turborepo
Frontend: React 18 + Vite + Tailwind CSS + React Router
Backend: NestJS + TypeScript
Banco de dados: PostgreSQL 15
ORM: Prisma
Autenticação: JWT próprio (access token + refresh token)
IA (futuro): API Claude (Anthropic) para busca semântica e geração de tags
Hospedagem de vídeos: Vimeo (embed via iframe + Player API)
Viewer de PDF: PDF.js (Mozilla) para leitura in-app

2.2 Modelo de Dados (PostgreSQL 15 + Prisma)
ATENÇÃO: As migrations só devem ser criadas com autorização explícita do PO. O schema abaixo é referência.

Tabela: tenants — id, name, createdAt, updatedAt
Tabela: users — id, tenantId (FK), name, username, email, whatsapp, password (hash), role (ENUM: MASTER, ADMIN, PROFESSOR), status (ENUM: PENDENTE, ATIVO, INATIVO), createdAt, updatedAt
Tabela: acervos (types) — id, tenantId (FK), name, icon, createdAt
Tabela: colecoes (categories) — id, acervoId (FK), tenantId (FK), name, createdAt
Tabela: conteudos (products) — id, colecaoId (FK), tenantId (FK), title, description, mediaType (ENUM: VIDEO, PDF), mediaUrl, imageUrl, isFeatured, tags (text[]), aiSummary, createdAt, updatedAt
Tabela: favorites — id, userId (FK), conteudoId (FK), createdAt
Tabela: ratings — id, userId (FK), conteudoId (FK), score (1-5), createdAt
Tabela: progress — id, userId (FK), conteudoId (FK), progressPercent, lastPosition, updatedAt
Tabela: refresh_tokens — id, userId (FK), token, expiresAt, createdAt

5. Regras de Negócio Importantes
RN-01: Senha nunca é definida pelo admin. O usuário sempre define a própria senha no primeiro acesso ou via link de redefinição.
RN-02: Exclusão de município só é permitida se não houver usuários vinculados.
RN-03: Exclusão de acervo remove em cascata todas as coleções e conteúdos vinculados.
RN-04: Conteúdo pode ser movido entre coleções (drag &amp; drop) e entre acervos (drop no pill + seleção de coleção).
RN-05: Professor com status PENDENTE não consegue fazer login.
RN-06: Tags e resumo gerados pela IA são editáveis — o admin tem a palavra final.
RN-07: O campo de busca inteligente (IA) só retorna conteúdos do tenant do professor logado.
RN-08: Progresso de vídeo é salvo a cada pausa e ao fechar; progresso de PDF é salvo pela página atual.
RN-09: Refresh token expira em 7 dias; access token em 15 minutos.
RN-10: Todo endpoint da API valida tenantId via middleware para garantir isolamento de dados.

6. Migrations (PostgreSQL 15 + Prisma)
⚠️ IMPORTANTE: As migrations NÃO devem ser criadas automaticamente. O desenvolvedor deve apresentar o schema Prisma proposto ao PO para aprovação antes de executar prisma migrate dev.

Ordem sugerida de migrations:
Migration 01: create_tenants — tabela base de municípios
Migration 02: create_users — tabela de usuários com roles e status (depende de tenants)
Migration 03: create_acervos — tipos de conteúdo por tenant
Migration 04: create_colecoes — categorias dentro dos acervos
Migration 05: create_conteudos — produtos com metadados, tags e IA summary
Migration 06: create_favorites — favoritos do professor
Migration 07: create_ratings — avaliações por estrelas
Migration 08: create_progress — progresso de consumo
Migration 09: create_refresh_tokens — tokens de refresh para JWT
Migration 10: create_rls_policies — Row Level Security por tenantId
